## 실행 범위

- 현재 spec 132 S45부터 계약 작성·검토·구현·검증·재현 가능한 보완을 이어간다.
- 저장소의 확정된 리빌드 요구를 근거로 후속 스펙을 작성·검토하고 다음 단위로 진행한다.
  기존 `current-spec-only` 및 `auto_start_next_spec: false`의 스펙 사이 정지 규칙은 이 위임 범위에서 해제된다.
- 최신 사용자 결정에 따른 Codex/Claude 역할과 현재 스펙의 정확한 파일·계약 범위를 따른다.
- 일반 커밋 및 기존 승인 목적지 `origin/rebuild/modern-studio`로의 fast-forward push를 허용한다.
  현재 스펙의 검증·전송 조건을 충족하고 실제 결과를 문서에 기록한다.
- 스펙별 자동 검증과 검수는 계속 수행한다. 사용자의 최종 검증은 자동 검증을 대신하지 않는다.
- 새 제품 결정, 스펙 밖 API·스키마·의존성, 운영 데이터·secret, 실제 Firebase/live 접근,
  Hosting·배포·운영본 변경, 실기기 검증은 기존 승인 경계를 유지한다.
- 기존 실패를 삭제·skip·완화하거나 추정 PASS로 기록하지 않는다. 보호 파일과 사용자 변경을 보존한다.
  최대 3회 보완 및 안전한 Git 처리 등 기존 루프의 나머지 중지 조건은 유지한다.
