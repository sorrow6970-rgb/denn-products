# 결정: 보안 및 개인정보 정책

결정일: 2026-07-21

상태: **확정 · 보안 관련 필수 계약**

## 핵심 결정

> 시안 비밀번호와 고객 개인정보는 브라우저 저장소·로그에 평문으로 남기지 않는다. 관리자 권한은 Firebase Security Rules에서 강제하며, 공개 쓰기 경로는 기존 호환을 유지하면서 App Check·익명 인증·용량·보관 정책으로 단계적으로 강화한다.

## 1. 관리자 인증과 권한

- 관리자 기능은 Firebase Email/Password 인증을 사용한다.
- 비익명 인증 여부를 서버 Security Rules에서 검증한다.
- UI에서 기능을 숨기는 것만으로 권한을 보호하지 않는다.
- 인증 전 관리자 데이터 다운로드를 허용하지 않는다.
- 로그인 오류에 계정 존재 여부를 과도하게 노출하지 않는다.
- 세션 만료나 권한 실패를 저장 성공으로 표시하지 않는다.
- 다중 관리자와 역할 권한이 필요하면 별도 스펙으로 설계한다.

## 2. 개인정보 범위와 최소 수집

다음을 개인정보 또는 민감한 고객 데이터로 취급한다.

- 이름, 연락처, 카카오 관련 식별 정보
- 주문 메모
- 업로드 사진과 시안
- 비공개 시안 토큰과 링크
- 고객을 식별할 수 있는 접속·오류 정보

필요한 정보만 수집하고 수집 목적을 사용자에게 표시한다. 테스트 데이터에 실제 고객 정보를 사용하지 않는다.

## 3. 시안 비밀번호와 토큰

- 시안 비밀번호를 localStorage, IndexedDB 또는 일반 로그에 평문 저장하지 않는다.
- 관리자 목록에 비밀번호 원문을 표시하지 않는다.
- 기존 `denn_proof_spaces` 평문 비밀번호 구조를 신버전에 복제하지 않는다.
- 비밀번호는 암호화 키 파생에만 사용하고 저장하지 않는다.
- `?space=<token>`은 비밀 링크로 취급한다.
- 토큰이 오류 로그, 분석 로그, referrer에 남지 않도록 설계한다.
- 기존 링크 호환은 유지하되 신규 링크 계약 변경은 버전·마이그레이션 스펙으로 처리한다.

## 4. 업로드 보안

- 파일 크기 상한을 강제한다.
- 허용 MIME과 실제 디코딩 가능 여부를 확인한다.
- SVG, HTML, 실행 파일 등 불필요한 형식을 차단한다.
- 원본 파일명을 Storage 경로로 직접 사용하지 않는다.
- 예측하기 어려운 안전한 경로를 생성한다.
- 공개 고객 에셋과 비공개 관리자 에셋 경로를 분리한다.
- 업로드 후 다운로드와 CORS-clean Canvas 사용 가능성을 검증한다.
- 이미지 메타데이터 제거 정책은 이미지 파이프라인 스펙에서 결정한다.

## 5. Firebase 공개 쓰기 정책

현행 공개 쓰기 계약은 기존 호환성 때문에 사용자 승인 없이 즉시 변경하지 않는다. 동시에 영구 불변 규칙으로 고정하지 않는다.

검토 대상:

- Firestore `spaces/{token}` 공개 create
- Storage `temp-share/**`, `proofs/**` 공개 write

신버전 보안 스펙에서 다음을 평가한다.

- Firebase App Check
- 익명 인증 의무화
- 파일당·사용자당 크기 제한
- 업로드 빈도 및 비용 통제
- 오래된 임시 파일 정리
- 콘텐츠 유형 제한
- 남용 탐지와 비용 경보

Rules 변경은 기존 링크 호환 분석, Emulator 테스트, 마이그레이션·롤백 계획, 사용자 승인을 요구한다.

## 6. 웹 애플리케이션 보안

- 사용자 입력은 기본적으로 텍스트로 렌더링한다.
- 임의 `innerHTML` 사용을 금지한다.
- HTML 렌더링이 필요하면 허용 목록 기반 정화와 별도 검토를 요구한다.
- 외부 URL은 허용 스킴을 검증하고 `javascript:` 등 위험 스킴을 거부한다.
- 외부 창에는 필요한 `noopener`·`noreferrer`를 적용한다.
- CSP 도입 가능성을 배포 스펙에서 검토한다.
- Firebase 웹 설정의 공개 값과 실제 비밀을 구분한다.
- 서비스 계정, 개인 키, 관리자 비밀은 클라이언트 코드와 Git에 포함하지 않는다.

## 7. 로그와 오류

- 비밀번호, 토큰, 연락처, 사진 데이터, base64를 로그에 기록하지 않는다.
- 운영 로그는 최소 오류 코드와 익명 상관 ID만 사용한다.
- 사용자 안내와 개발 진단 정보를 분리한다.
- 빈 `catch`와 실패 무시를 금지한다.
- 네트워크·인증·저장 실패를 성공으로 처리하지 않는다.
- 디버그 기능은 운영에서 기본 비활성화한다.
- 디버그 화면에 민감 정보가 나타나지 않도록 테스트한다.
