## 2. E-4 — 인쇄 파일명

### 확정 형식

```
denn-frame-21x29.7cm-20260731-153042.png
```

- 접두사 `denn-frame-` 고정
- **cm 치수**: `projectFramePrintPhysicalSize`가 돌려준 `widthCm`x`heightCm`.
  파일이 없다면 치수도 없으므로(P-2) **항상 존재한다**
- 타임스탬프: **로컬 시각** `YYYYMMDD-HHmmss`
- 소문자·숫자·하이픈·점만. 공백·한글·특수문자 **없음**

### 왜

- **고객 문구·id·token은 절대 넣지 않는다.** 파일명은 저장이자 전송이다 — P-5c의
  "고객 문구는 텍스트로 저장·전송하지 않는다"가 **파일명에도 그대로 적용**된다.
- **사이즈 이름 대신 cm을 쓴다.** 레거시는 `safeName(sz.name)`으로 **이름**을 넣었다.
  이름은 운영자가 언제든 바꿀 수 있어 **같은 물건의 파일명이 시점마다 달라진다**.
  cm은 인쇄물의 **물리적 사실**이고 인쇄소가 실제로 필요로 하는 정보다.
  (P-2가 "이름을 바꾸면 인쇄가 바뀌는 동작은 제품 사고"라고 한 것과 같은 방향이다.)
- **읽을 수 있는 타임스탬프.** 레거시 `Date.now()` epoch 밀리초는 사람이 못 읽고
  파일 목록에서 시간순 정렬도 안 된다.
- 문자 집합을 좁히는 이유는 OS·인쇄소 업로드 폼에서 깨지지 않게 하기 위해서다.

### 남는 것 (Codex 구현 계약이 정할 것)

- cm의 소수점 표기(예: `29.7` vs `29.70`)와 소수점 문자를 파일명에 그대로 쓸지
- 같은 초에 두 번 내려받을 때의 중복 처리(브라우저가 `(1)`을 붙이는 기본 동작에 맡길지)

## 3. E-5 — 다운로드 UI 위치·문구·비활성 사유

### 3.1 위치

- 미리보기 캔버스 **아래**, 편집 컨트롤과 **구분된 독립 영역**.
- **카카오 주문 CTA와 붙이지 않는다.** P-4a로 **주문 전송은 차단**된 상태이므로,
  주문 버튼 옆에 두면 "이걸 누르면 주문이 들어간다"는 오해를 만든다.
  레거시 V36은 정확히 그렇게 배치해 **다운로드·IndexedDB 주문 저장·카카오 열기를 한 흐름**으로
  묶었다 — 이번에는 **분리**한다.

### 3.2 문구

| 요소 | 문구 |
| --- | --- |
| 버튼 | **`인쇄용 파일 내려받기`** |
| 임시값 안내(항상 표시) | **`인쇄 설정은 인쇄소 확인 전 임시값입니다.`** |
| cm 미입력·무효로 비활성 | **`이 사이즈는 아직 인쇄용 파일을 만들 수 없습니다.`** |
| 미리보기 미완성으로 비활성 | 기존 `PREVIEW_MESSAGES`의 해당 사유를 **재사용**(새 문구를 만들지 않는다) |
| 생성 실패 | **`인쇄용 파일을 만들지 못했습니다.`** |

- 버튼에 **"주문"이라는 말을 쓰지 않는다** — 실제로 주문이 되지 않기 때문이다.
- 실패 문구에 **"다시 시도해 주세요"를 넣지 않는다.** 자동 retry가 0이고, 같은 조건이면
  같은 결과가 나온다. 될 것처럼 안내하는 쪽이 더 나쁘다.
- 모든 문구는 **고정 문자열**이다. 코드·id·파일명·URL·예외 메시지·수치를 **담지 않는다**
  (`previewContracts.ts`의 `PREVIEW_MESSAGES` 규율 그대로).

### 3.3 접근성

- 비활성 버튼은 **`disabled` + 사유 문구를 `aria-describedby`로 연결**한다.
  `disabled`만 두면 스크린리더가 **이유를 읽지 못해** 고객이 원인을 알 수 없다.
- 스펙 031 텍스트 입력이 이미 같은 방식을 쓰고 있으므로 **새 패턴이 아니다**.

## 4. E-6 — provisional 상수를 UI에 노출할지

### 확정: **수치는 노출하지 않는다. "임시 설정"이라는 사실만 밝힌다.**

- 고객 화면에 `300dpi` · `3000` · `36,000,000px` 같은 **숫자를 보여주지 않는다.**
- 대신 **`인쇄 설정은 인쇄소 확인 전 임시값입니다.`** 한 줄만 표시한다(E-5의 안내 문구와 동일).
- 결과 PNG의 픽셀 크기도 **고객 UI에 표시하지 않는다.** 레거시는
  `r.canvas.width+'×'+r.canvas.height+'px'`를 상태줄에 찍었지만, 이는 운영자용 정보이고
  고객에게는 의미가 없다. 필요하면 **내려받은 파일 자체로 확인**할 수 있다.

### 왜

- P-4a가 요구한 것은 **"임시값임을 명시"** 이지 **"수치를 노출"** 이 아니다.
- 이 수치들은 **인쇄소 확인 후 바뀔 예정**이다. 고객이 기억하면 바뀌었을 때 오히려 혼란이 된다.
- `PREVIEW_MESSAGES` 규율이 이미 **UI 문구에 수치·코드를 담지 않는다**로 서 있다.
  여기서 예외를 만들면 그 규율이 약해진다.

## 5. 이 결정이 만드는 불변식

1. **파일명에 고객 문구·id·token이 들어가지 않는다.** 치수와 시각만 들어간다.
2. **사이즈 이름은 파일명에 쓰지 않는다** — 이름이 바뀌어도 파일 추적이 깨지지 않는다.
3. **다운로드 버튼은 주문 CTA와 분리**되어 있고 **"주문"이라는 말을 쓰지 않는다.**
4. **비활성 사유는 항상 읽을 수 있다**(`aria-describedby`).
5. **UI 문구에 코드·수치·id·URL·예외가 들어가지 않는다.**
6. **임시값이라는 사실은 밝히되 수치는 밝히지 않는다.**
