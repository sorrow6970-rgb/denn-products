# 결정: 품질 게이트 정책

결정일: 2026-07-21

상태: **확정 · 병합 및 배포 차단 조건**

## 핵심 결정

> 타입·lint·테스트·빌드·Firebase Rules·E2E·모바일·시각 회귀를 필수 게이트로 둔다. 실패하거나 필수 항목이 미검증이면 병합·배포하지 않는다. 긴급 우회는 사용자 승인과 24시간 이내 보완을 조건으로 한다.

## 1. 3단계 게이트

### 개발 커밋 전

- format check
- lint
- TypeScript 검사
- 변경 영역 유닛 테스트
- 금지 패턴 검사
- 신규 파일과 의존성 범위 확인

빠른 검사는 통상 2분 이내 실행을 목표로 한다.

### 브랜치 병합 전

- 전체 타입·lint
- 전체 유닛·통합 테스트
- 프로덕션 빌드
- 핵심 Playwright E2E
- 데이터 fixture·마이그레이션
- 접근성 검사
- viewport 시각 회귀
- Firebase Emulator Rules 테스트
- 의존성 취약점과 비밀정보 검사

### Preview·프로덕션 전

- 배포 대상과 검증 커밋 일치
- Preview URL 실동작
- 실제 모바일 환경
- 업로드·저장·게시·시안·주문
- 기존 데이터 읽기 호환
- CORS-clean Canvas와 인쇄 PNG
- 성능 예산
- 백업·롤백 절차

## 2. 0건 통과 조건

- TypeScript 오류
- lint 오류
- 실패 테스트
- 프로덕션 빌드 오류
- Rules 테스트 실패
- 알려진 데이터 손실
- 민감정보 노출
- 주요 화면 수평 overflow
- 버튼 겹침·이탈
- 처리되지 않은 런타임 오류
- 예상하지 않은 테스트 콘솔 오류

경고도 이유와 제거 작업 번호 없이 누적하지 않는다.

## 3. TypeScript

- `strict: true`
- 의미 없는 `any` 금지
- `@ts-ignore` 기본 금지
- 예외에는 이유와 제거 조건 기록
- 외부 입력은 런타임 스키마 검증
- Firebase·웹 저장소 결과를 직접 신뢰하지 않음
- `null`·`undefined` 처리 명확화

## 4. 테스트 기준

- 핵심 로직 라인 커버리지 최소 80%
- 마이그레이션·암호화·저장·렌더 수학 최소 90%
- UI는 커버리지 숫자보다 행동 검증 중심
- 전체화면·회전·Firebase는 E2E 필수
- 의미 없는 커버리지 채우기 테스트 금지

## 5. 버그 수정

```text
실패하는 재현 테스트
→ 원인 확인
→ 최소 수정
→ 재현 테스트 통과
→ 관련 회귀검증
```

테스트 없는 시간값 변경, 증상 은폐 조건문, 오류 무시, 단일 기기 1회 성공만으로 승인하지 않는다.

## 6. 핵심 E2E

- 관리자 인증
- 기존 데이터 읽기
- 개발 저장소 저장
- 템플릿 생성·수정
- 게시 데이터 생성과 고객 로드
- 이미지 업로드
- 액자·케이스 렌더링
- 룸·전체화면
- 시안 암·복호화
- 주문 생성·조회·다운로드
- 오류·오프라인·재접속

기능 추가 시 관련 E2E를 같은 작업에 포함한다.

## 7. 시각·접근성 회귀

소형/일반 모바일, 모바일 가로, 태블릿, 데스크톱과 빈·로딩·오류·모달·대량 데이터 상태를 검증한다.

- 스크린샷 차이
- overflow와 겹침
- 최소 터치 크기
- 키보드 탐색과 포커스
- 명암비
- 접근 가능한 이름

기준 이미지 갱신은 의도한 변경임을 검토·승인한 뒤 수행한다.

## 8. 테스트 격리

- 운영 Firebase 자동 테스트 금지
- Emulator 또는 별도 테스트 프로젝트 사용
- 테스트별 데이터 초기화
- 실행 순서 비의존
- 시각·난수·네트워크 통제
- 실제 고객 fixture 금지
- 실패 후 테스트 데이터 정리

## 9. Flaky 테스트

- 단순 재실행 성공 처리 금지
- 간헐 실패도 결함으로 기록
- 소유 작업 없는 장기 skip 금지
- `skip`, `only`, 임의 retry를 CI에서 검사
- 고정 sleep 대신 관측 가능한 상태 조건 사용

## 10. CI 순서

```text
lockfile install
→ format
→ lint
→ typecheck
→ unit/integration
→ build
→ rules
→ e2e
→ visual/accessibility
→ security checks
```

- lockfile 불일치 실패
- 로컬·CI 명령 통일
- 필수 job 실패 시 병합 금지
- 배포는 전체 필수 job 성공 후만 가능

## 11. 완료 보고

- 커밋 해시와 변경 파일
- 실행 명령과 개별 결과
- Preview URL(해당 시)
- 수동·실제 기기 검증 여부
- 미검증 항목과 알려진 위험
- 롤백 방법

`테스트 완료`라는 요약만으로 승인하지 않는다.

## 12. 긴급 예외

운영 중단 방지 핫픽스만 사용자 승인 아래 제한적으로 우회할 수 있다.

- 최소 변경
- 롤백 준비
- 배포 직후 재현 테스트
- 24시간 이내 전체 보완 검증 또는 롤백
