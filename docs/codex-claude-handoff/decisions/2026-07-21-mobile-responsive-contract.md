# 결정: 모바일 반응형 및 기기 호환 계약

결정일: 2026-07-21

상태: **확정 · 출시 차단 조건**

적용 대상: 신규 리빌드의 고객 화면, 관리자 화면, 비공개 시안, 모달, 에디터, 룸·전체화면 UI 전체

## 목표

신버전은 특정 모바일 시안 크기에만 맞추지 않는다. 화면 크기, 화면 비율, 브라우저 UI, 노치, safe area, 입력 키보드, 회전 상태가 달라도 콘텐츠와 버튼이 밀리거나 겹치거나 잘리지 않아야 한다.

이 계약을 통과하지 못한 화면은 데스크톱에서 정상이어도 완료로 인정하지 않는다.

## 1. 지원 원칙

- 기기 모델명별 하드코딩을 금지한다.
- CSS viewport와 실제 사용 가능 영역을 기준으로 적응한다.
- 너비뿐 아니라 높이와 화면 비율도 고려한다.
- 고정 픽셀 좌표에 의존해 주요 UI를 배치하지 않는다.
- 콘텐츠 확대·축소로 문제를 숨기지 않는다.
- 터치 기기에서 hover를 필수 상호작용으로 사용하지 않는다.
- 기능은 세로·가로 회전 후에도 유지된다.
- 모바일과 데스크톱은 동일 데이터·도메인 계약을 사용한다.

## 2. 필수 레이아웃 범위

최소 다음 범위를 설계·검증한다.

- 소형 모바일: CSS width 320px 이상
- 일반 모바일: 360–430px
- 대형 모바일 및 폴더블 단일 화면
- 태블릿 세로·가로
- 데스크톱 좁은 창과 일반·대형 화면
- 낮은 높이의 모바일 가로 화면
- 확대 텍스트 및 200% 브라우저 확대

임의의 대표 기기 이름만 통과하는 방식이 아니라 범위 내 연속 너비에서 레이아웃이 유지돼야 한다.

## 3. Viewport와 Safe Area

- `100vh` 단독 의존을 금지한다.
- 지원 브라우저에서는 `dvh`를 우선 사용하고 필요한 `svh`/`lvh` fallback을 정의한다.
- 상·하단 고정 UI는 `env(safe-area-inset-top|right|bottom|left)`를 반영한다.
- iPhone 노치·Dynamic Island·홈 인디케이터 영역을 침범하지 않는다.
- 모바일 주소창의 표시·숨김으로 Canvas, 바텀시트, CTA가 튀지 않아야 한다.
- viewport 변화는 한 개의 공식 레이아웃 계층에서 처리한다.

## 4. 버튼과 조작 영역

- 주요 터치 대상은 최소 44×44 CSS px를 보장한다.
- 버튼·아이콘 간 충분한 간격을 둔다.
- 주요 CTA는 잘리거나 다른 고정 UI에 가려지지 않는다.
- 라벨이 길어지거나 시스템 글꼴 크기가 커져도 버튼 밖으로 밀려나지 않는다.
- 필요하면 줄바꿈, 최소/최대 폭, 스크롤 또는 우선순위 축소를 명시적으로 사용한다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.

## 5. 모바일 키보드

- 입력 포커스 시 키보드가 필드와 저장·주문 버튼을 가리지 않는다.
- Visual Viewport 변화에 대응하되 여러 컴포넌트가 각각 보정하지 않는다.
- 키보드 표시 중 바텀시트와 하단 내비게이션이 중첩되지 않는다.
- 포커스된 입력은 사용 가능 영역 안으로 이동하되 사용자의 스크롤을 반복 강제하지 않는다.
- 키보드 닫힘 후 스크롤·Canvas 위치가 원래 상태로 안정적으로 복구된다.

## 6. 바텀시트·모달·고정 UI

- 바텀시트는 최소·중간·최대 높이 상태를 명시한다.
- 내부 콘텐츠가 넘치면 시트 내부만 스크롤되며 페이지와 이중 스크롤 경쟁을 만들지 않는다.
- 닫기·확정 버튼은 safe area 위에 유지한다.
- 모달은 작은 높이와 가로 모드에서 화면 밖으로 벗어나지 않는다.
- 하단 내비게이션, CTA, 바텀시트가 같은 영역을 동시에 점유하지 않도록 단일 레이아웃 소유자가 조정한다.

## 7. Canvas와 미디어

- Canvas의 CSS 크기와 backing-store 해상도를 분리하고 DPR을 반영한다.
- 레이아웃 변경 시 이미지 비율·프레임 앵커·사용자 배치 값이 변하지 않는다.
- 회전과 resize에서 렌더링 상태는 보존되고 UI만 재배치된다.
- 이미지와 Canvas가 컨테이너를 밀어내지 않도록 `min-width:0`, `min-height:0`, 명시적 비율·contain 규칙을 사용한다.
- 인쇄 결과 해상도는 화면 viewport와 독립적이어야 한다.

## 8. 전체화면과 회전 상태 머신

전체화면은 명시적 단일 상태 머신으로 관리한다.

```text
idle → entering → active → exiting → settling → idle
```

- 동일 전환의 중복 실행을 차단한다.
- 스크롤·화면 잠금·회전·마스크를 변경하는 권한은 하나만 둔다.
- 임의의 다중 `setTimeout` 보정과 함수 래핑을 금지한다.
- 진입·종료·회전 중 사용자 선택과 Canvas 상태를 보존한다.
- 브라우저가 Fullscreen API를 지원하지 않거나 거부할 때 정상적인 비전체화면 fallback을 제공한다.

## 9. 반응형 구현 규칙

- 공통 토큰과 레이아웃 컴포넌트를 사용한다.
- breakpoint는 콘텐츠가 깨지는 지점을 기준으로 정하고 임의의 기기명으로 정하지 않는다.
- 컨테이너 쿼리가 더 적절한 독립 패널은 container query를 검토한다.
- 절대 위치는 Canvas 오버레이 등 명확한 좌표계가 필요한 영역으로 제한한다.
- 핵심 UI에 음수 margin이나 임의 translate 보정을 사용하지 않는다.
- `!important`로 반응형 충돌을 해결하지 않는다.
- JavaScript로 CSS 레이아웃을 반복 측정·덮어쓰는 방식을 피한다.

## 10. 필수 자동 검증 매트릭스

최소 다음 viewport를 Playwright 프로젝트 또는 동등한 자동 검증에 포함한다.

| 분류 | CSS viewport 예시 | 필수 방향 |
|---|---:|---|
| 소형 모바일 | 320×568 | 세로 |
| 일반 모바일 | 360×800 | 세로 |
| iPhone 계열 | 390×844 | 세로·가로 |
| 대형 모바일 | 430×932 | 세로·가로 |
| 소형 태블릿 | 768×1024 | 세로·가로 |
| 데스크톱 | 1280×800 | 가로 |
| 대형 데스크톱 | 1440×900 이상 | 가로 |

각 화면에서 다음을 자동 확인한다.

- 수평 페이지 overflow 없음
- 주요 버튼 viewport 밖 이탈 없음
- 요소 간 비의도 겹침 없음
- 텍스트 잘림 없음(의도적 ellipsis 제외)
- 최소 터치 크기
- 모달과 바텀시트의 사용 가능 영역
- 스크린샷 회귀

## 11. 실제 기기 검증

에뮬레이션만으로 완료 판정하지 않는다. 주요 릴리스 전 최소 다음 실제 환경을 확인한다.

- iPhone Safari
- Android Chrome
- 카카오톡 인앱 브라우저
- 가능한 경우 Samsung Internet

각 환경에서 다음을 반복한다.

- 첫 로드와 재접속
- 이미지 업로드
- 입력 및 키보드 열기/닫기
- 세로↔가로 회전
- 전체화면 진입·종료 반복
- 내 공간 바텀시트·모달
- 저장·주문 CTA
- 뒤로 가기와 복귀

## 12. 완료 및 승인 조건

화면별 스펙은 다음 근거를 포함해야 한다.

- 자동 viewport 매트릭스 결과
- 대표 스크린샷
- overflow·겹침·터치 크기 검사 결과
- 실제 기기 검증 결과 또는 아직 미검증이라는 명시
- 발견된 예외와 롤백 방법

버튼 밀림, 겹침, 가려짐, 의도하지 않은 수평 스크롤, 회전 후 상태 손실 중 하나라도 재현되면 출시 차단 결함으로 처리한다.
