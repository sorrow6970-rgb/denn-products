# 결정: 운영 전환·배포·롤백 정책

결정일: 2026-07-21

상태: **확정 · 배포 작업의 필수 계약**

## 핵심 결정

> 기존 운영본을 유지한 채 신버전을 `local → preview → 단계적 cutover`로 전환한다. 문제 발생 시 15분 이내 Hosting 롤백, 30분 이내 기존 서비스 복귀를 목표로 하며 기존 버전은 전환 후 최소 90일 보관한다.

## 1. 기존 운영본 보존

- 기존 HTML과 Firebase Hosting 설정을 전환 전까지 현재 위치에 유지한다.
- 기존 파일을 먼저 이동·삭제·이름 변경하지 않는다.
- 실제 프로덕션과 일치하는 커밋을 확인한 뒤 운영 기준선 태그를 만든다.
- 기존 `/`와 `/denn-admin.html` 경로를 cutover 전까지 유지한다.
- 기존 운영본에는 긴급 장애, 데이터 손실, 보안 문제만 최소 수정한다.

## 2. 리빌드 격리

- 신버전은 별도 리빌드 브랜치와 신규 디렉터리에서 개발한다.
- 기존 프로덕션 파일과 신규 빌드 산출물을 섞지 않는다.
- 스펙 단위로 커밋하고 각 커밋은 독립적으로 검증·복구 가능해야 한다.
- 생성된 빌드 산출물은 별도 요구가 없는 한 Git에 커밋하지 않는다.

## 3. 환경 분리

```text
local      개발자 로컬, 테스트 데이터만 사용
preview    Firebase Preview Channel, 통합·실제 기기 검증, 운영 쓰기 금지
production 현재 고객 서비스, 사용자 승인 배포만 허용
```

- 환경별 Firebase 경로, 기능 플래그, 설정을 명시적으로 분리한다.
- URL만 다르고 동일 운영 데이터 경로에 쓰는 구성을 금지한다.
- 테스트 데이터와 운영 데이터를 혼용하지 않는다.

## 4. 권한과 승인

- Claude Code가 코드 수정·테스트·커밋·푸시를 담당한다.
- Preview 배포는 사용자 승인 후 수행한다.
- 프로덕션 배포 전 대상 커밋·변경 범위·영향을 사용자에게 보고한다.
- Codex는 배포를 수행하지 않고 배포 전후 상태와 결과를 검증한다.
- Hosting, Firebase Rules, 데이터 마이그레이션은 각각 별도 승인 대상으로 취급한다.
- 여러 독립 변경을 한 번에 묶어 배포하지 않는다.

## 5. Preview 품질 게이트

프로덕션 전에 최소 다음을 통과한다.

- 빌드, 타입, lint, 유닛 테스트
- 핵심 E2E
- 기존 데이터 읽기 호환
- 모바일 viewport 매트릭스와 실제 기기
- Firebase 인증과 Security Rules
- 이미지 업로드와 CORS-clean Canvas
- 저장, 게시, 시안, 주문 흐름
- 성능 및 오류 로그
- 구버전 결과 비교

Preview URL과 검증 커밋 해시를 기록한다.

## 6. 단계적 전환

```text
내부 Preview
→ 제한 사용자 시험
→ 운영 데이터 읽기 전용 연결
→ 최종 동기화·쓰기 중지 시간 확정
→ 신버전 쓰기 권한 전환
→ Hosting 경로 전환
→ 집중 모니터링
→ 안정화 후 구버전 보관 단계 전환
```

고객·관리자 화면은 가능하면 위험도와 데이터 계약에 따라 단계적으로 전환한다. 반드시 함께 전환해야 한다면 단일 cutover 스펙에 근거를 기록한다.

## 7. 배포 전 체크포인트

- 승인된 커밋 해시
- 신규 릴리스 태그
- 기존 운영 기준선 태그
- Firebase Rules 버전
- 운영 데이터 백업
- 이전 Hosting 릴리스
- 마이그레이션 dry-run 결과
- 검증 담당과 시간
- 롤백 명령과 예상 소요 시간

## 8. 즉시 롤백 조건

- 데이터 저장·복원 실패
- 기존 데이터 누락·오염
- 로그인·게시·주문 차단
- 이미지 업로드·인쇄 출력 실패
- 기존 `?space=` 링크 불능
- 주요 모바일 환경에서 화면 사용 불가
- 버튼 겹침·이탈 등 모바일 출시 차단 문제
- 오류율 또는 로드 실패 급증
- Security Rules 오작동

문제가 발생하면 추가 패치로 계속 전진하지 않고 우선 신버전 쓰기를 중지하고 롤백한다.

## 9. 롤백 목표

- Hosting 롤백: 15분 이내
- 신버전 운영 쓰기 중지: 즉시
- 기존 서비스 재개: 30분 이내
- 데이터 복구: 변경 유형별 사전 계획 적용
- 원인 분석과 재검증 전 재배포 금지

앱 롤백만으로 복구되지 않는 데이터 변경을 피하기 위해 원본 불변과 쓰기 권한 전환 방식을 우선한다.

## 10. 전환 후 보관

- 기존 HTML과 기준선 태그를 최소 90일 보관한다.
- 안정화 기간 동안 구버전 복귀 경로를 유지한다.
- 안정화 전 기존 Storage 파일과 운영 데이터를 삭제하지 않는다.
- 폐기가 필요하면 별도 폐기 스펙, 백업, 사용자 승인을 요구한다.
- 구버전 제거는 리빌드 완료와 별도 사용자 결정이다.

## 11. 금지 사항

- 기존 운영 파일을 먼저 이동·삭제
- Preview 검증 없는 프로덕션 배포
- 배포와 데이터 마이그레이션의 즉흥 동시 실행
- 테스트·운영 Firebase 경로 혼용
- 검증하지 않은 커밋 배포
- 배포 후 롤백 절차 작성
- 장애 중 연속 패치로 전진
- 사용자 승인 없는 운영 변경
