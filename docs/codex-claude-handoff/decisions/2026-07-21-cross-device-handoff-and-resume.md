# 결정: PC 간 핸드오프 및 작업 재개 정책

결정일: 2026-07-21

상태: **확정 · 작업 시작과 종료의 필수 절차**

## 재개 신호

사용자가 **“이어가자”**, **“계속하자”**, **“집에서 이어서 하자”** 또는 같은 의미로 말하면 Codex와 Claude Code는 즉시 구현하지 않는다. 먼저 이 문서의 재개 점검을 수행하고 결과를 사용자에게 보고한다.

## 핵심 원칙

> 브랜치, 커밋, lockfile, CURRENT, 현재 spec, 테스트 결과가 원격에 반영된 상태를 작업 기준으로 사용한다. 로컬과 원격이 일치한다는 확인 전에는 수정·설치·배포하지 않는다.

## 1. 작업 종료 절차

PC를 떠나거나 세션을 종료하기 전에 Claude Code는 다음을 수행한다.

1. `git status --short --branch`
2. 현재 브랜치와 upstream 확인
3. 해당 스펙의 필수 검사 실행
4. 변경 파일과 diff 검토
5. `CURRENT.md`와 스펙의 DONE 또는 결과 문서 갱신
6. 목적별 커밋
7. 일반 push
8. 원격 브랜치에 같은 커밋이 반영됐는지 확인
9. 최종 커밋 해시와 미검증 항목 보고

강제 push는 금지한다.

## 2. 다른 PC에서 재개 절차

다음 순서로 진행한다.

1. 저장소 경로 확인
2. `git status --short --branch`
3. 미커밋 변경 유무 확인
4. 현재 브랜치와 upstream 확인
5. `git fetch --prune`
6. 로컬·원격 ahead/behind 확인
7. 작업 브랜치로 안전하게 전환
8. 작업 트리가 깨끗할 때만 `git pull --ff-only`
9. HEAD와 원격 브랜치 커밋 일치 확인
10. 필수 문서 읽기
11. 런타임·lockfile·환경 준비 확인
12. 기본 검증 실행
13. 사용자에게 재개 가능 여부 보고

예상하지 않은 merge commit을 만드는 일반 `git pull`은 사용하지 않는다.

## 3. 필수 문서 읽기

1. `/CLAUDE.md`
2. `docs/rebuild/README.md`
3. `docs/codex-claude-handoff/README.md`
4. `docs/codex-claude-handoff/CURRENT.md`
5. 현재 작업에 적용되는 `decisions/`
6. 현재 `docs/rebuild/specs/NNN-*.md`
7. 최신 DONE·review·실제 기기 결과

## 4. 로컬 변경이 있을 때

- 미커밋 변경이 있으면 pull·브랜치 전환을 중단한다.
- 변경 파일, diff, 생성 주체와 목적을 확인한다.
- 사용자 작업인지 자동 생성물인지 추정만으로 삭제하지 않는다.
- stash·commit·복원 중 어떤 처리가 맞는지 사용자에게 보고한다.
- `git reset --hard`, 강제 checkout, 강제 clean을 사용하지 않는다.

## 5. 원격이 앞서 있을 때

- 작업 트리가 깨끗하면 `git pull --ff-only`만 허용한다.
- fast-forward가 불가능하면 자동 merge·rebase하지 않는다.
- 서로 다른 커밋과 변경 파일을 비교해 사용자에게 보고한다.

## 6. 로컬이 앞서 있을 때

- 커밋 내용과 테스트 결과를 확인한다.
- 원격에 없는 이유를 확인한다.
- 스펙 범위와 일치하면 일반 push를 제안한다.
- 다른 PC에서 같은 브랜치가 갱신됐을 가능성이 있으면 먼저 fetch 후 재검증한다.

## 7. Git으로 동기화되지 않는 항목

재개 시 별도로 확인한다.

- `.env`와 비밀정보
- Firebase CLI 로그인
- 브라우저 로그인·쿠키
- 실제 고객·운영 데이터
- git-ignored backup 파일
- Emulator 로컬 데이터
- 커밋되지 않은 영상·스크린샷
- Node·pnpm 등 전역 런타임

비밀정보를 Git에 추가해서 해결하지 않는다.

## 8. 런타임 재현성

스캐폴드 이후 다음을 저장소에 고정한다.

- Node 버전
- pnpm 버전
- 단일 lockfile
- 환경변수 예시—비밀값 제외
- 설치·개발·빌드·테스트 명령
- Emulator 설정

의존성은 lockfile 고정 설치를 사용한다.

## 9. 브랜치 역할

- `main`: 승인된 문서와 기존 이력 보존
- `rebuild/modern-studio`: 승인된 리빌드 스펙 구현
- `prod-baseline-20260721`: 실제 production 비교 기준 태그

브랜치 역할이 변경되면 별도 사용자 결정과 문서 갱신이 필요하다.

## 10. 재개 판정

Codex 또는 Claude Code는 다음 중 하나로 보고한다.

- `재개 가능`: 로컬·원격·문서·런타임 기준 일치
- `정리 후 재개`: 안전하게 처리 가능한 차이 존재
- `재개 중단`: 충돌·미확인 변경·환경 누락으로 사용자 결정 필요

## Claude Code 반영 지시

Claude Code는 사용자가 재개 의사를 밝히면 이 절차를 먼저 수행한다. 점검 전 코드 수정, 의존성 설치, 브랜치 병합, 배포를 하지 않는다.
