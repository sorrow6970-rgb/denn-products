## 1. Founder 승인 (제품·UX·정책 결정)

| ID | 결정 | 승인 내용 |
| --- | --- | --- |
| **R-1** | 각도 집합 | 고객 사진 회전은 **90° 배수만** 지원한다. UI는 **`왼쪽 90°` / `오른쪽 90°` 버튼**을 사용한다 |
| **R-2** | D-3/D-7 재해석 | **임의 각도를 도입하지 않는다** → 스펙 029의 `scale` **1.0~5.0**과 **클립 안 빈 공간 금지** 계약을 **그대로 유지**한다 |
| **R-3** | 액자 가로/세로(aspect 전환) | **별도 기능으로 분리**하고 **이번 스펙에서 제외**한다. 사진 회전과 액자 aspect 전환을 한 상태로 묶지 않는다 |
| **R-4** | case multi-zone | case에도 **활성 슬롯별 독립 회전**을 제공한다. 한 슬롯의 회전이 다른 슬롯에 전파되지 않는다 |
| **R-5** | 아트 템플릿(028) | **template art는 고정**하고 **사용자 사진만 회전**한다 |
| **R-6** | EXIF 정규화 | **EXIF를 직접 파싱하지 않는다**. 브라우저 `<img>` decode 동작에 의존하고, **합성 EXIF fixture로 실측**해 근거를 남긴다 |

### 승인 근거 요약

- **R-1 / R-2**: 임의 각도는 스펙 029 Founder 확정값과 **수학적으로 충돌**한다 — 45°에서 cover 최소 배율이 √2라 `scale` 하한 **1.0(D-3)** 과 **빈 공간 금지(D-7)** 를 동시에 만족할 수 없다(조사 §5.2). 90° 배수면 스펙 019 cover(입력 w/h swap 재사용)와 029 normalized pan이 **그대로** 살아 있다(§5.1).
- **R-3**: 레거시는 사진 회전과 액자 aspect를 한 상태(`state.rot`)로 묶어 **케이스 사진 오염**과 **미리보기≠인쇄**를 만들었다(조사 §2, §4). `resolveOrientedAspect`가 이미 분리된 축을 제공하므로 분리가 구조적으로도 자연스럽다.
- **R-4**: 레거시에 케이스 회전 UI는 없었고, 있는 것처럼 보인 것은 `T.rot ?? state.rot` **전역 폴백 버그**였다(§2.2). 슬롯별 소유로 두면 그 결함을 재현하지 않는다.
- **R-5**: 아트는 `stretch`로 캔버스/mat에 고정돼 있어 사진 회전과 독립이다. 시각적 정합은 운영자 책임이다.
- **R-6**: 직접 파싱은 **이중 회전 위험**과 **신규 의존성**을 부른다(§7). 다만 리빌드의 `<img>`+`naturalWidth` 경로는 이 저장소에서 **실측된 적이 없으므로**(NOT VERIFIED) 합성 EXIF fixture 실측을 검증 항목으로 남긴다.

## 2. Codex 구조 계약 (C-1~C-9, 같은 라운드에서 확정 — 원문 보존)

| ID | 결정 |
| --- | --- |
| **C-1** | `rot`의 저장 위치는 스펙 029 normalized transform의 **네 번째 필드**(`{scale, x, y, rot}`)다. 전역 상태 금지 → composer의 **슬롯별** transform이 소유하며 D-9 초기화 행렬을 자동 상속한다 |
| **C-2** | 저장 값은 **`0|1|2|3`**(quarter turn) 집합으로 한정한다. 그 밖의 값은 **복구 없이 거부**한다(clamp 복구·기본값 생성 금지 — 029와 동일 규율) |
| **C-3** | pan은 **화면축**을 유지한다. `maxPan`은 **회전된 footprint**로 다시 계산한다 → 회전 토글 시 normalized 값은 유지하고 환산만 다시 한다 |
| **C-4** | 회전 중심은 **zone 중심 + 현재 pan**이다 → 회전 시 구도 점프가 없다 |
| **C-5** | plan 어휘는 `draw-image-cover`의 **선택적 `rotationQuarterTurns`** 로 확장한다(명시 없으면 기존과 동일 결과). 신규 커맨드를 만들지 않는다 |
| **C-6** | executor는 한 command 안에서 **`save → translate(중심) → rotate → drawImage → restore`** 를 수행한다. 기존 "no transform" 문구는 "**커맨드 내부에서만, 반드시 restore와 짝지어**"로 정정한다 |
| **C-7** | adapter는 029의 **probe plan(pan 0) → `maxPan` → 실제 plan** 파이프라인을 유지하되 **probe plan에도 회전을 포함**하고 normalized 값을 유지해 재환산한다 |
| **C-8** | 회전은 **plan에 기록**한다 → 향후 print/export 스펙이 같은 plan을 소비하면 자동으로 일치한다. "UI만 회전"은 레거시 결함(§4)의 재생산이므로 금지한다 |
| **C-9** | 실패 우선순위는 029 §3 순서를 유지하고 회전 검증을 **transform 유한성·범위 검증 단계에 편입**한다. 회전 검증 실패도 **plan 미생성**(부분 plan 금지)이다 |

## 3. 이 결정이 만드는 불변식

1. 회전 값은 **quarter turn 집합 밖에서 존재하지 않는다** — 거부이며 복구가 아니다.
2. 회전은 **슬롯별**이다. 전역 회전 상태·전역 폴백은 만들지 않는다(레거시 케이스 오염 재현 금지).
3. **scale 하한 1.0과 빈 공간 금지(029 D-3·D-7)는 그대로 유지**된다 — 회전이 이 두 계약을 완화하지 않는다.
4. 회전은 **plan에 담긴다** — 미리보기와 인쇄가 같은 plan을 소비해 구조적으로 일치한다.
5. **template art는 회전하지 않는다** — 회전 대상은 사용자 사진뿐이다.
6. **액자 가로/세로 aspect 전환은 이번 스펙의 범위가 아니다.**
7. **EXIF를 직접 파싱하지 않는다** — 신규 의존성 0, 이중 회전 0.

## 4. 이 결정에 포함되지 않은 것 (여전히 미결정·미검증)

- 액자 **가로/세로 aspect 전환** 기능 자체(R-3으로 분리) → 별도 스펙 필요
- `packages/render` 계약 변경의 정확한 범위·문구(C-5·C-6은 방향이며 구현 스펙이 확정한다) — 지금까지 지켜 온 "`packages/**` 무변경" 경계를 **처음 깨는 일**이다
- 브라우저 `<img>` decode의 실제 EXIF 적용 여부 → **NOT VERIFIED**, 합성 fixture 실측 전까지 PASS 아님
- 실기기 4환경(iOS Safari · Android Chrome · 삼성 인터넷 · 카카오 인앱)에서의 회전 UI 조작성 → 육안 검증 필요
- print/export 경로의 실제 회전 재현(현재 인쇄 경로는 회전을 무시) → 별도 스펙
- 임의 각도의 향후 도입 여부(R-1·R-2로 1차 제외)
- 대용량 사진에서 회전 시 성능·메모리
