## 판정

**디자인 방향 승인 / 구현 규격은 보완 후 재검증**

화이트·뉴트럴 구조, 테라코타 포인트, 라운드 카드, 카카오 CTA를 조합한 Modern Studio 방향은 네 화면에서 일관되며 DENN의 고객 편집기·관리자 콘솔·비공개 시안 경험을 하나의 브랜드로 묶는 기준으로 적합하다.

## 승인된 기준

- Modern Studio(B) 무드
- 테라코타 `#C0614A`를 주 포인트로 사용
- 카카오 CTA의 고정 노랑과 검정 텍스트
- 고객 데스크톱의 좌측 도구/중앙 캔버스/우측 속성 구조
- 고객 모바일의 프리뷰+바텀시트 구조
- 관리자 사이드바+요약 카드+업무 목록 구조
- 비공개 시안의 큰 장면+주문 확인 정보 구조
- 공통 토큰을 통한 앱 간 시각 일관성

## 구현 전 필수 보완

### 1. 접근성 색상 검증

`#C0614A` 위 흰색 텍스트, muted 텍스트, 성공색 조합을 WCAG 대비 기준으로 실제 계산한다. 정상 본문은 4.5:1, 큰 텍스트·아이콘은 적용 조건에 맞는 기준을 충족해야 한다. 미달 조합은 시각 방향을 유지하면서 토큰 값을 조정한다.

포커스 링, 키보드 탐색, 오류 상태는 색상만으로 구분하지 않는다.

### 2. 상태 토큰 확장

현재 성공 상태만 정의돼 있다. 다음 토큰과 컴포넌트 상태를 추가한다.

- danger/error
- warning
- info
- disabled
- hover
- pressed
- focus-visible
- loading/skeleton
- empty state
- destructive confirmation

### 3. 반응형 규격 수치화

데스크톱·모바일 시안 사이의 전환 규칙을 명시한다.

- breakpoint
- 데스크톱 3영역의 최소·최대 폭
- 캔버스 최소 크기와 비율 유지
- 모바일 바텀시트 최소/중간/최대 높이
- safe-area inset
- 소프트 키보드가 열린 상태
- 모바일 가로 모드
- 태블릿 중간 레이아웃
- 작은 높이 화면에서 CTA와 내비게이션 충돌 방지

### 4. 모바일 입력 컴포넌트 정정

모바일 시안의 문구 입력은 브라우저 기본 input처럼 표시되어 확정된 radius·padding·border 토큰과 불일치한다. 실제 구현 시 공통 Input 컴포넌트를 사용하고 키보드 표시 중에도 주문 CTA와 입력이 가려지지 않도록 한다.

### 5. 내비게이션 전체 기능 매핑

시안은 대표 구조이지 전체 기능 명세가 아니다. 구현 전에 레거시 기능 인벤토리를 다음으로 분류한다.

- 1차 출시 내비게이션에 직접 노출
- 하위 화면/상세 메뉴로 이동
- 기능 플래그로 후속 제공
- 폐기 후보

관리자 시안에 표현되지 않은 템플릿 제작, UI 설정, 내보내기 등 기존 기능을 누락으로 간주하지 않도록 별도 IA 표가 필요하다.

### 6. 편집 상태와 데이터 상태 정의

다음 화면 상태의 와이어프레임 또는 규격을 추가한다.

- 이미지 없음/업로드 중/업로드 실패
- 저장 중/저장 성공/충돌/복구
- 템플릿 없음/검색 결과 없음
- 오프라인 또는 Firebase 실패
- 비밀번호 입력 전·오류·만료된 시안
- 데이터가 많은 관리자 테이블
- 모바일 전체화면 진입·종료

### 7. 시안과 기능 계약 분리

PNG 시안은 시각적 참고이며 픽셀 그대로 구현하는 절대 계약이 아니다. 기능 배치, 실제 데이터 밀도, Canvas 비율, 모바일 브라우저 제약을 반영하면서 디자인 토큰과 정보 계층을 보존한다.

## 001 스펙 관련 제한

- 첫 스캐폴드에서 기존 `denn-mockup-tool.html`과 `denn-admin.html`을 이동하거나 삭제하지 않는다.
- 신규 앱은 별도 경로로 추가한다.
- 디자인 토큰과 최소 UI 패키지 골격까지만 만들고 전체 화면 구현은 후속 화면별 스펙으로 분리한다.
- 기술 스택이 사용자에게 확정되기 전 의존성을 설치하지 않는다.
