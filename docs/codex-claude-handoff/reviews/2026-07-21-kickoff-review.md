## 판정

**수정 후 재검증**

전체 리빌드, 기능·데이터 계약 보존, Codex 분석/Claude Code 구현 역할 분리는 올바르다. 그러나 작업 001의 기준선 동결·복구 가능성·승인 경계가 아직 완료되지 않았고, 일부 문구는 확인되지 않은 사항을 확정값으로 취급한다.

## 반드시 수정할 사항

### 1. 운영 기준선이 아직 동결되지 않음

현재 `main`과 `origin/main`은 `623a929`에서 일치한다. 그러나 이 커밋이 실제 프로덕션과 동일하다는 배포 증거와 전용 기준선 태그가 없다.

Claude Code는 태그나 브랜치를 임의 생성하지 말고 사용자에게 다음을 먼저 보고한다.

- 실제 라이브가 `623a929`와 동일한지 확인할 방법
- 추천 기준선 태그 이름
- 리빌드 브랜치 이름
- 기존 Firebase Hosting으로 즉시 되돌리는 절차

프로덕션 일치가 확인되기 전에는 `623a929`를 운영 기준선이라고 단정하지 않는다.

### 2. 작업 트리 정리가 완료되지 않음

Codex 분석기가 갱신한 다음 파일이 여전히 수정 상태다.

- `docs/hot-functions-2026-05-17.md`
- `docs/patch-inventory-2026-05-17.md`

이 변경은 애플리케이션 수정이 아니라 분석 스크립트 부산물이다. Claude Code는 사용자 변경이 없음을 재확인한 뒤 두 파일만 `HEAD` 상태로 복원하고 결과를 보고한다. 신규 킥오프 및 전달 문서는 보존한다.

### 3. 기존 HTML은 초기 단계에서 이동하지 말 것

킥오프는 첫 스캐폴드에서 기존 `denn-*.html`을 `legacy/`로 이동하도록 제안한다. 현재 Firebase Hosting은 루트의 `denn-mockup-tool.html`과 `denn-admin.html`에 직접 의존하므로 이동은 기존 배포·로컬 실행·롤백 경로를 깨뜨릴 수 있다.

리빌드 초기에는 기존 파일을 제자리에 유지한다. 참조 복사본이 필요하면 별도 복사 여부를 사용자에게 승인받되, 중복 대용량 파일을 Git에 추가할 필요가 있는지도 먼저 검토한다. 실제 이동은 신버전 cutover 스펙에서만 수행한다.

### 4. Firebase 공개 쓰기 규칙을 '절대 그대로 보존'으로 고정하지 말 것

기존 링크와 데이터 계약의 호환은 보존해야 하지만 다음 공개 쓰기 정책은 보안·비용 위험 검토 대상이다.

- Firestore `spaces/{token}`의 인증 없는 create
- Storage `temp-share/**`, `proofs/**`의 인증 없는 write

리빌드가 기존 동작을 깨뜨리면 안 된다는 원칙과, 취약한 운영 정책을 영구 고정한다는 원칙은 다르다. `CLAUDE.md`에는 이를 "호환 유지가 필요한 현행 계약이며, 별도 보안 스펙과 마이그레이션 계획 없이 변경 금지"로 표현한다. App Check, rate/size/retention 통제, 인증 전환 가능성은 별도 의사결정 대상으로 남긴다.

### 5. '전수 분석 완료' 표현을 제한할 것

`00-legacy-analysis.md`는 좋은 1차 인벤토리지만 실제 데이터 샘플, 모든 관리자 저장 흐름, 기존 `?space=` 토큰 라운드트립, 실제 기기 전체화면, Firebase 배포 상태까지 검증한 전수 분석은 아니다.

문서 제목 또는 서두에 다음 한계를 명시한다.

- 정적 코드 및 로컬 비파괴 로드 중심
- 운영 데이터 샘플 미검증
- 실제 Firebase write/read E2E 미검증
- 모바일 실제 기기 회귀 미검증
- 기능 인벤토리는 후속 계약 조사에서 보완 가능

### 6. 기술 스택은 아직 확정하지 말 것

현재 스택은 제안 상태로 유지한다. 특히 프레임워크·라우터·상태관리·UI 라이브러리의 버전은 스캐폴드 직전에 공식 문서 기준으로 검증하고 잠근다. 사용자의 명시적 확정 전에는 의존성 설치나 프로젝트 생성을 하지 않는다.

## 유지해도 좋은 내용

- 두 앱의 공통 로직을 패키지로 분리
- Canvas 2D 렌더 엔진을 UI 프레임워크와 분리
- 기존 데이터와 `?space=` 링크의 호환 테스트
- CORS-clean 인쇄 출력 계약
- 스펙 단위 구현·커밋·검증
- Codex가 범위와 완료 조건을 작성하고 Claude Code가 구현하는 역할 분리
