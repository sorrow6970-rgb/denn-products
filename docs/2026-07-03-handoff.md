### 2. 보안 B — 운영자 Firebase Auth + 관리자 클라우드 동기화 (`denn-admin.html`)
- **로그인**: 로컬 하드코딩 비번(denn2024) → `signInWithEmailAndPassword`. 익명 제거, non-anon만 `_ready`. 세션 지속(재방문 자동진입, `dennOnAuthStateV`). **계정은 Firebase 콘솔서 생성**(Email/Password 공급자 켜기 + Users 추가).
- **클라우드 동기화**: Storage `admin/state.json`(비공개). `dennCloudSaveAdminV`(저장 펀넬 훅, 디바운스 3s) + `dennCloudLoadAdminV`(로그인 시 `getBytes`). 충돌=`__cloudRev` 최신우선 + `mergeAdminStateSafe`. 하이드레이션 가드(`__dennHydratedV`)로 로컬 클로버 방지. → **어느 기기서든 로그인=최신 관리자 데이터.**
- **storage.rules(보안B)**: ★Firebase는 겹치는 match를 OR → catch-all `read:if true`가 admin/까지 노출. **경로별 명시 match**로: admin/(op()만), temp-share·proofs(익명write), published·templates·placeholders·guides·mockups·editor-overlays(공개read+op()write). `op()=auth!=null && sign_in_provider!='anonymous'`. read조건에 request.resource.size 금지. 검증: admin/=403·published/=200.
- 개념: **💾저장=로컬+클라우드백업**(운영자 기기동기화) / **📢게시=소비자 공개**.

### 4. ★★★ 발행본 데이터 안 뜨는 치명 버그 해결 (신규 소비자 전원 영향) — `denn-mockup-tool.html`
- **증상**: localStorage 있는 브라우저만 정상, 시크릿/신규/모바일은 fetch 됨(490943b)인데 denn_admin=1037B·ADM=0sizes.
- **근본원인**: 발행본 apply가 `setItem+saveAdminToIdb→location.reload()→dbGet` 라운드트립 의존. 시크릿/모바일서 reload 미발동 or IDB 커밋 실패 → 490KB 유실. + 첫 로드 빈 ADM으로 여러 load 핸들러(saveSettingsV33/loadAdminFresh→persistAdmin/writeAdminV48)가 기본값 1037B 저장, 490KB와 경쟁해 덮음. (기존데이터 프로필은 실데이터라 안덮여 정상=깨끗한 환경만 깨짐.)
- **수정**:
  - (a) 발행본 객체를 `window.__dennPublishedDataV`로 **메모리 직접 전달** + `window.__dennPubReadyV` promise, **리로드 완전 제거**. init(load, `denn-mockup-tool.html` L~2361)이 promise await 후 메모리 데이터를 바로 ADM으로 사용(IDB/reload 무의존).
  - (b) `window.__dennPubLoadingV` gate를 **부트 IIFE 시작부터 true**, init이 실데이터 확정 직후에만 false. 그 전 모든 기본값 저장 4경로(saveCustomerAdminStateToLocalStorage/writeAdminDbV48/persistAdmin) 차단. 안전TO 10s.
  - (c) **자가치유**: 가드(`denn_pub_synced`) 켜졌어도 로컬 denn_admin에 frameSizes 없으면(무효) 가드 무시 재fetch → **이미 오염된 기기도 새로고침만으로 자동 복구**.
- **검증**: 시크릿 초기화후 콘솔 `[boot] ADM set from published | frameSizes=9`, LS=490943·ADM=9sizes. ★부수효과=첫로드 리로드 깜빡임/느림 해소.
- 진단: `?debug=1`(부트 상태박스), `?share=published/state.json`(가드 우회 강제로드).

### ① 주소창 빈 공간 / 상단 간격 (dvh 레이아웃) — 매핑 완료, 바로 착수 가능
**증상**: 모바일서 브라우저 주소창이 나타났다 사라질 때 상단 메뉴(탭바)와 액자 미리보기 사이에 빈 공간 생김 + 상단 간격 어긋남.
**원인**: `#page-frame.main.on` 컨테이너 높이가 `svh`(주소창 있는 작은 뷰포트 고정값)라 주소창 토글 시 라이브 뷰포트와 안 맞음. 중앙정렬(justify-center) 목업이 어긋나며 빈공간. `95px` 헤더 상수도 실제(~60px)와 불일치.
**수정 (모두 `denn-mockup-tool.html`, `#page-frame` 스코프 — 케이스탭/룸모달 무영향)**:
- **L12672** `#page-frame.main.on{...height:calc(100vh - 95px);height:calc(100svh - 95px)...}` → `100svh`를 **`100dvh`**로, `95px`를 실헤더(~60px)로.
- **L2755/L2756** `#page-frame .preview-area{min-height:50vh!important}` / `46vh` → **제거**(L12673의 `flex:1 1 auto`가 이미 남은공간 채움) 또는 dvh화.
- 건드리지 말 것: `body{min-height:100vh}`(L65)·`.main{...}`(L80)=케이스탭 공유 / `denn-mobile-layout-v1`(L9665)=케이스 split-pane 공유 / `#room-modal`(별도 오버레이) / `#frameCanvas{touch-action:none}`(L12603, 유지).
