## 수정 라운드 2 — Codex 2차 판정 "수정 후 재검증": orientation lock 비동기 종료 경합 (2026-07-21)
- 문제: `so.lock('landscape')` await 중 사용자가 FS 종료 또는 detach 시, 늦은 lock 성공이 `locked=true`/결과 `locked`를 stale 복원하거나, 정상 잠금 후 종료해도 `lockResult`가 `locked`에서 안 풀려 화면이 실제와 불일치.
- 수정(`src/lib/fullscreen.ts`):
  1. **세대 토큰** `lockGen` — 모든 lock 시도 시작 시 `++`, 종료(`doUnlockOrientation`)·detach 시 `++`로 in-flight 무효화.
  2. **순수 `isLockStillValid({attemptGen,currentGen,detached,state,inFullscreen})`** — Promise 완료 시 동일 요청·비detach·`active`·실제 FS 재확인. 유효할 때만 `locked` 기록(유닛 5건).
  3. **늦은 성공(무효)** → `releaseOrientation()`로 안전 unlock, `locked` 미기록.
  4. **종료 후 초기화** — settling 시 결과 `locked→idle`.
  5. **detach 후 통지 차단** — `detached` 플래그로 `setLockResult`/`dispatch` 조기 return(React 상태 갱신·listener 통지 없음), 보유 lock 안전 해제.
  - 단일 상태 권위·단일 rAF 유지, 임의 timer 없음.
- 재검증: typecheck ✅ / unit ✅ **18/18**(+5 경합) / build ✅ JS gzip 66.25KB / e2e ✅ 10/10. 운영파일 무변경. **실기기 lock 동작 NOT TESTED 유지.**

## 수정 라운드 3 — Codex 3차 판정 "수정 후 재검증": React StrictMode 재attach 생명주기 (2026-07-21)
- 문제: StrictMode(dev)가 effect를 attach→detach→attach로 재실행. `detach()`가 `detached=true`로 두는데 `attach()`가 복구하지 않아, 재attach 후 `dispatch()`/`setLockResult()`가 계속 조기 return → Fullscreen 상태 관측·orientation lock 처리가 비활성화될 수 있음.
- 수정(`src/lib/fullscreen.ts` `attach()`):
  1. **재attach 복구**: attach 시 `detached=false` 재설정 → dispatch/통지 재활성.
  2. **세대 분리 유지**: attach 시 `lockGen++`로 새 세션 시작 → 이전 세대의 늦은 lock Promise는 `isLockStillValid`(gen 불일치)로 계속 무효 → 새 세션 상태 덮어쓰지 못함.
  3. **단일 attach 정책**: attach 시작에 기존 `onChange` handler 제거 후 새 handler 등록 → 중복 listener 방지.
  4. **detach 클로저 캡처**: 각 detach는 자신의 handler만 제거(`this.onChange` 대신 지역 `handler` 참조) → 순서 무관 안전.
  - 단일 상태 권위·단일 rAF 유지, 임의 timer 없음.
- 테스트 추가:
  - `tests/unit/fullscreen-controller.test.ts` (DOM 목, jsdom 미사용): attach→detach→attach 후 dispatch 재활성(state→entering→active)·단일 listener·중복 attach 정리 (3건).
  - `tests/e2e/fullscreen.spec.ts`: FS 요청 버튼 클릭 → 상태 처리 또는 정상 fallback 메시지 관측(실제 FS 성공 강제 안 함, 고정 sleep 없이 auto-wait), console error 0.
