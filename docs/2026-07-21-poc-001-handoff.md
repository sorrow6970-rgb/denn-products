## 수정 라운드 2 — Codex 2차 판정 "수정 후 재검증": orientation lock 비동기 종료 경합 (2026-07-21)

### 증상 (4환경 공통 재현: iPhone Safari · Android Chrome · Samsung Internet · 카카오 인앱)
- 핀치 확대 시 하단 고정 CTA(`.bottomnav`, `App.tsx:344`)가 **과도하게 커지고 좌우가 잘리며 본문을 크게 가림.**
- 기본 배율 1~14는 PASS. 브라우저 한정 아님 → **POC 공통 레이아웃 문제.** 증거 `KakaoTalk_20260721_212105638.jpg`.

### 원인 (두 뷰포트의 상호작용)
- 모바일은 **레이아웃 뷰포트**(문서 기준, 예: 411 CSS px)와 **비주얼 뷰포트**(현재 보이는 영역, 핀치 확대 시 스케일↑·크기↓)가 분리돼 있다.
- **`position:fixed`는 레이아웃 뷰포트 기준으로 배치·렌더된다**(비주얼 뷰포트 아님). 따라서 사용자가 핀치로 `scale=2` 확대하면:
  1. 고정 바가 배율만큼 **확대 렌더**(과도하게 커짐).
  2. 바 폭이 `left:0;right:0` = **레이아웃 뷰포트 전체 폭**(411px)이라, 확대로 좁아진 비주얼 뷰포트(≈보이는 205px)를 넘어 **좌우가 잘림**.
  3. 바가 레이아웃 뷰포트 하단에 앵커되어, 확대·패닝된 화면에서 **본문 위를 덮음**.
- 즉 **브라우저의 표준 핀치 확대 동작과 POC의 `position:fixed` 레이아웃 선택 사이의 호환성 결함**(특정 브라우저 버그가 아니라, 모든 모바일 공통 동작 위에서 우리 레이아웃 선택이 어긋남). 확정 결함 대상 = `.bottomnav`(`styles.css:269`).
- **위험 후보(미확정):** `.sheet-backdrop`/`.sheet`도 `position:fixed`라 동일 취약 **가능성**이 있으나, **아직 실기기 재현 없음** → 수정 범위 포함·FAIL 확정하지 않음. 별도 재현으로 확인 후 판단.
- 참고: `useViewportOwner`(`App.tsx:56`)는 이미 `visualViewport` resize/scroll을 구독하지만 **키보드 inset(`--kbd-inset`)만** 반영하고 **확대(scale/offset) 대응은 없음.** viewport meta는 `user-scalable` 미제한(확대 허용, 접근성상 올바름) → 확대 자체를 막는 건 금지.

### 확정 수정 방향 (사용자 결정 2026-07-21 · Codex 구현 스펙 대기 · 코드 미변경)

A안을 기반으로 재설계. **구현은 Codex 구현 스펙 발행 후에만 진행**한다(현재 코드·CSS·테스트 무변경).

- `visualViewport.scale`이 **확대 상태**일 때 기존 `.bottomnav`를 `position:fixed`에서 **문서 흐름**으로 전환한다.
- `.bottomnav`가 이미 `main` 뒤(DOM 말단)에 있으므로 **별도 중복 CTA(구 C안)는 만들지 않는다.**
- **확대 해제 시** `.bottomnav`를 `position:fixed`로 정상 복귀한다.
- 확대 상태에서는 `.content`의 고정 CTA용 **하단 여백 120px(`styles.css:122`)도 함께 정상화**한다(흐름 전환 시 불필요한 빈 공간 제거).
- **scale 경계값과 상태 전환은 순수 함수로 테스트**한다(단일 레이아웃 소유자 유지, 새 전역·임의 timer 없음).
- **구 B안(비주얼 뷰포트 역스케일·좌표 추적)은 사용하지 않는다.**
- **bottom sheet(`.sheet-backdrop`/`.sheet`)는 별도 재현 전까지 수정하지 않는다.**

### 검증안 (수정 시)
- 자동: typecheck / unit(레이아웃 소유자의 scale 분기 순수함수 유닛) / build(번들 예산) / e2e viewport(회귀). e2e에 `visualViewport.scale` 강제는 헤드리스 한계로 **부분** — 실기기 필수.
- 수동(실기기 4환경): 200%/핀치 확대에서 **(a) 확대 상태에서 CTA 전체에 도달·조작 가능하고, CTA가 본문을 지속적으로 가리지 않음** (b) 주문 CTA 클릭 동작 (c) 기본배율 1~14 회귀 없음. device-matrix 확대 게이트 행 갱신.

- 접근성: axe(위반 0 유지), `user-scalable` 제한 도입 금지 재확인.
